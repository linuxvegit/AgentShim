# Plan P03 — `PolicyVec<T>` contract hardening (v0.6.1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Source design:** [`docs/superpowers/specs/2026-05-13-v0.6.1-p04-closure-design.md`](../specs/2026-05-13-v0.6.1-p04-closure-design.md) §3.3 + §4.3.

**Goal:** Closes M-7. Today `crates/router/src/resilient_caller.rs:240-285` carries an unwritten invariant — `chain.len() == retry_policies.len() == breaker_policies.len()` — enforced by `.truncate()` calls plus runtime `debug_assert_eq!`s. This plan replaces both with a typed `PolicyVec<T>` wrapper that makes mismatched-length construction impossible at every call site.

**Architecture:** A new `pub(crate) struct PolicyVec<T>` in `crates/router/src/policy_vec.rs`. Internal-only wrapper around `Vec<T>` whose constructor enforces `policies.len() == expected_len` at the type level. The internal call chain (`complete()` → `complete_inner_with_optional_filter` → `complete_inner_summary` → `complete_inner`) gets refactored to thread `PolicyVec`s instead of bare `Vec`s. The public `complete()` API stays unchanged (still accepts `Vec<RetryPolicy>` and `Vec<BreakerPolicy>`) — the wrapping happens at the boundary, so existing call sites (production gateway state + ~10 test sites) require zero edits. The runtime `debug_assert_eq!`s vanish because the type system now enforces the invariant.

**Tech stack:** No new external deps. Standard `thiserror` for the construction error.

**Frozen-core impact:** No core or frontends changes. Internal-only `pub(crate)` wrapper in router. No new public API on the `agent-shim-router` crate.

**Test target:** 675 (going in, after P02) → 677 (+2 PolicyVec constructor tests). Counts may run higher if positive-path tests are also tallied — P03 adds 5 PolicyVec unit tests; the net gain over runtime-asserted invariants is 2 (the constructor mismatch test + retain_first behaviour test).

```rust
//! Typed length-invariant wrapper around `Vec<T>`. Plan v0.6.1 P03 (M-7).
//!
//! `PolicyVec<T>` carries a `Vec<T>` plus a `paired_len: usize` that the
//! constructor enforces equal to `vec.len()` at construction time. The
//! internal callers in `resilient_caller.rs` use this to thread the
//! "one policy per chain element" invariant through the type system,
//! replacing the v0.6.0 `.truncate()` + `debug_assert_eq!` pattern.

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn new_accepts_matched_length() {
        let v = PolicyVec::new(vec![1u8, 2, 3], 3).expect("matched len");
        assert_eq!(v.as_slice(), &[1, 2, 3]);
        assert_eq!(v.len(), 3);
    }

    #[test]
    fn new_rejects_mismatched_length() {
        let err = PolicyVec::new(vec![1u8, 2, 3], 4).expect_err("len mismatch");
        match err {
            PolicyVecLenError { actual, expected } => {
                assert_eq!(actual, 3);
                assert_eq!(expected, 4);
            }
        }
    }

    #[test]
    fn retain_first_shortens_in_place_preserving_invariant() {
        let mut v = PolicyVec::new(vec![1u8, 2, 3], 3).unwrap();
        v.retain_first(2);
        assert_eq!(v.as_slice(), &[1, 2]);
        assert_eq!(v.len(), 2);
    }

    #[test]
    fn retain_first_no_op_when_count_equals_len() {
        let mut v = PolicyVec::new(vec![1u8, 2, 3], 3).unwrap();
        v.retain_first(3);
        assert_eq!(v.as_slice(), &[1, 2, 3]);
    }

    #[test]
    fn into_inner_returns_the_vec() {
        let v = PolicyVec::new(vec![1u8, 2, 3], 3).unwrap();
        assert_eq!(v.into_inner(), vec![1, 2, 3]);
    }
}
```

Above the `#[cfg(test)] mod tests { ... }` block, add the struct + error type with just-enough API to make the tests *compile*, but with bodies that all return wrong answers — so the tests fail at the assertion level rather than the compile level (giving us a clean RED → GREEN transition).

```rust
use thiserror::Error;

/// Error returned by [`PolicyVec::new`] when the supplied vector's
/// length doesn't match the expected paired length.
#[derive(Debug, Clone, PartialEq, Eq, Error)]
#[error("policy vector length mismatch: got {actual}, expected {expected}")]
pub struct PolicyVecLenError {
    pub actual: usize,
    pub expected: usize,
}

/// A `Vec<T>` whose length matches the chain it pairs with by
/// construction. Internal to the router crate.
#[derive(Debug, Clone)]
pub struct PolicyVec<T> {
    inner: Vec<T>,
}

impl<T> PolicyVec<T> {
    /// Construct, enforcing `items.len() == expected_len`. Returns
    /// [`PolicyVecLenError`] otherwise.
    pub fn new(items: Vec<T>, expected_len: usize) -> Result<Self, PolicyVecLenError> {
        // INTENTIONALLY WRONG for Step 2 — fixed in Step 4.
        Ok(PolicyVec { inner: items })
    }

    pub fn len(&self) -> usize {
        self.inner.len()
    }

    #[allow(dead_code)]
    pub fn is_empty(&self) -> bool {
        self.inner.is_empty()
    }

    pub fn as_slice(&self) -> &[T] {
        &self.inner
    }

    /// Shorten the inner vector to its first `n` elements, preserving the
    /// length-paired invariant when the caller is also shortening the
    /// paired chain to the same `n`.
    pub fn retain_first(&mut self, n: usize) {
        self.inner.truncate(n);
    }

    /// Drop the wrapper; return the inner `Vec`.
    pub fn into_inner(self) -> Vec<T> {
        self.inner
    }
}

impl<T> std::ops::Index<usize> for PolicyVec<T> {
    type Output = T;
    fn index(&self, i: usize) -> &T {
        &self.inner[i]
    }
}
```
